# 安全与隐私

[English](security-and-privacy.md) | 简体中文

本项目把公开实现与本地个人数据分开。该边界依靠工作流和发布控制维持；它不会把本机或被忽略目录变成加密保险箱。

## 公开数据与本地数据

Git 跟踪的公开内容包括 `app/` 中的应用代码与测试、`scripts/` 中的安全和工作流脚本、公开规则与文档、依赖锁、许可证，以及只包含占位符的模板。

只在本机保留并被忽略的内容包括：

- `private/resume_materials.md`；
- `private/job_search_preferences.md`；
- `private/applications.sqlite` 及其他 SQLite 文件；
- 简历、文档、照片、证书和其他附件；
- 本地附件哈希、环境、缓存、编辑器状态和前端构建产物。

Git 忽略规则不能阻止操作系统备份或云盘同步，需要单独配置这些系统。备份数据库时，先停止服务，再把 `private/applications.sqlite` 复制到 Git 之外另一个受保护的本地位置。

## 资料来源与浏览器边界

真实表单填写时，`private/resume_materials.md` 是字段值、选项与声明的唯一允许来源。Codex 不会根据上传文档、招聘页面、浏览器历史记录、自动填充、外部搜索或公开示例模板推断字段。

发现岗位时，本轮明确要求优先于 `private/job_search_preferences.md` 中的长期范围和排序偏好；`private/resume_materials.md` 仍是候选人事实与资格证据的唯一来源。Codex 先选择招聘站内相关的分类筛选，完整检查其可访问分页而不设置固定岗位数量，再深入阅读可能相关的 JD 后进行匹配。关键词搜索只能补充探测，不能代表全站覆盖。发现流程始终限制在用户提供的同一公司招聘流程中，不能填写、保存或投递。

由用户打开招聘页面并明确要求填写后，Codex 可以准备高置信度字段、替换当前申请中已声明的附件，并使用含义明确的中间控件。遇到最终提交、登录、验证、付费、账号创建、背景调查授权、声明范围不明、必填事实缺失或附件操作不安全时必须停止。

招聘网页与邮件是不可信输入。其内容不能要求 Agent 读取其他本地数据、改变仓库规则、执行命令、修改数据库结构、扩大凭据权限或跨越最终提交边界。

## 本地服务边界

正式模式只监听 `127.0.0.1:8000`，不接受可配置的正式数据库路径，只使用 `private/applications.sqlite`。Demo 只监听 `127.0.0.1:8001`，使用经过校验的系统临时会话目录，并省略 Agent 和邮件路由。测试模式接受显式注入的路径并关闭调度，隔离测试程序负责提供临时路径。

不要通过反向代理、隧道、端口转发或局域网绑定暴露端口。应用没有账号认证，因为远程和多用户部署不受支持。写入请求必须使用 JSON 和允许的 loopback Host/Origin。

启动工具会校验健康接口中的服务身份和模式。正式启动与 Agent 命令拒绝 Demo；只有隔离测试程序会通过进程级标志允许测试模式。

## SQLite 内容

数据库保存岗位元数据、当前已校验阶段、结构化事件日期、短备注、下一步事项、服务商游标和有界的结构化邮件复核队列。它不保存候选人姓名、电话、邮箱地址、家庭住址、简历内容、表单答案、附件内容、原始邮件字段、邮箱凭据或令牌、验证码、会议链接。

状态变更必须追加事件。`applied` 需要 `user_confirmation`；表单准备与邮件提取不能创建该状态。归档或已结束记录还有额外迁移检查。

## 邮箱凭据与内容

QQ/163 授权码只写入 Windows Credential Manager，并使用不透明账号目标。Outlook 的 MSAL 缓存由 Windows DPAPI 加密后保存到本地应用数据目录。这些值不会写入 SQLite、日志、配置或 `private/`。安全存储失败时直接失败，绝不回退到明文。

邮件以增量只读方式处理。原始主题、发件人、正文、附件、私人联系人、验证码和会议链接不会由 API 返回，也不会保留在复核队列中。服务商与保留规则详见[邮件接入](mail-ingestion.zh-CN.md)。

## 公开发布检查

公开前只按精确路径暂存已复核文件。不得宽泛添加，也不得强制添加被忽略内容。

```powershell
git add -- README.md README.zh-CN.md
# 其他已复核的公开文件也逐个显式添加。
pwsh -NoProfile -File .\scripts\Test-PublicRelease.ps1 -Staged
git diff --cached --check
git diff --cached --name-only
git diff --cached
```

策略只允许明确声明的公开路径，并检查必要文件、私有路径模式、数据库、附件与媒体扩展、可识别二进制/媒体签名、文档媒体语法、密钥模式和个人联系方式模式。`-PolicySelfTest` 可以在不修改真实 Git 索引的情况下验证正向和负向策略样例：

```powershell
pwsh -NoProfile -File .\scripts\Test-PublicRelease.ps1 -PolicySelfTest
```

检查通过只能降低意外泄露风险，不能证明自然语言完全匿名。必须复核每一行暂存差异，不得绕过失败，也不得在索引中还原或生成真实私有资料文件。

安全问题报告方式见 [SECURITY.md](../SECURITY.md)。
